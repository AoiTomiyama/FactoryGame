# 特異点への累計納品と出荷を分けるゲームループ拡張計画

タグ: `実装計画` `採用方針` `特異点` `出荷` `累計納品` `ゲームループ`

更新日: 2026-11-11。状態: 出荷分離、累計納品、段階定義・達成判定・UIまで実装済み。対象検証の後に通し確認へ進むというユーザー指定に従い、統合と数量調整を次工程とする。ユーザーが1B・2B・3Aを選択し、小さな世界を育てる案から、ブラックホール風の特異点が吸収し続ける方針へ変更した。[コンセプト](../design/game-concept.md)を方針の正本とする。

## 問題・解決策・結論

着手時の問題: 特異点が換金を担い、生産拡大の先に納品目標がなかった。

解決策: 換金先を独立した出荷セルへ分け、特異点は累計納品と段階達成を担当する。収益を得る経路と、目標へ進む経路を工場の配置で分ける。

結論: 取引の分離、納品状態、初期配置、表示、統合検証の順に実装する。段階・最終目標を満たしても、特異点の吸収と工場の稼働は続ける。

## 採用した納品設計

品目別の累計納品数を保持し、各段階に設定した累計目標をすべて満たすと次へ進む。同じ品目の納品数は段階を跨いで保持する。目標判定と通貨入金は独立し、特異点への納品から残高を増やさない。出荷から納品進捗を増やさない。

納品数を更新するのは搬送成功後の確定時とする。予約・演出中断・取消・接続解除では増やさない。各ポートの予約は種別と全量を固定し、段階が変わっても成立済みの搬送を一度だけ確定できるようにする。

段階目標を跨ぐ搬送も分割せず全量を累計へ加える。目標を超えた分を取り消したり、同じ搬送を次段階へ二重加算したりしない。最後の必要数が搬送単位で割り切れなくても進行できるようにする。最終目標達成後も、設定された資源種の受入と累計記録を続ける。数量上限は予約時に検証し、確定時の算術失敗を防ぐ。

段階名・品目・必要個数をEditorから編集できる定義にまとめる。新しい独立設定アセットを作る場合は、初期配置と進行条件を別々に調整する用途に限定する。資源別の第二通貨や、別建てのポイントを追加しない。

## 実装順と完了条件

| 順序 | 対象 | 完了条件 |
| --- | --- | --- |
| 1 | 出荷セルと換金担当（実装済み） | 特異点への納品と出荷への換金が分離され、同じ資源から両方の成果を得ない。出荷は既存売価・残高上限・取消の契約を満たす |
| 2 | 累計納品・段階状態・定義（実装済み） | 種別ごとの確定数で判定し、中断でも進捗を保持する。多ポートの同時納品・一度に複数段階を満たすケース・再入・繰返し確定でも進捗と通知が重複しない |
| 3 | 初期配置・購入・Prefab（出荷セル分を実装済み） | 初期資金100で実際の換金経路を作れる。初期出荷先と特異点の占有が重ならず、追加出荷セルを既存の配置経路で購入できる。ModelとField／Placeholderを共用し、Sceneの既存編集を保つ |
| 4 | 納品目標・達成・吸収の表示（実装済み） | 次の必要品と確定数、現在の段階、最終目標達成が分かる。達成通知は一度だけで、達成後も生産・出荷・吸収・散策を続けられる。内部予約数や重複説明をUIへ追加しない |
| 5 | 統合と調整 | 出荷で得た収益による設置・スキル購入と、加工品の累計納品による最終目標達成を、一つのプレイ経路で確認する。必要個数を変えて再調整できる |

初期出荷セルは1×1の独立設備を基本案とする。配置場所、初回経路、追加購入価格、目標数量は最初の代表配置で調整してから展開する。基礎投入 → 一材料加工品 → 複合加工品の短い一周を先に作り、到達時間を確認する。外観画像の細部や背景演出はこの最初の機能確認と分けて制作する。

## 検証と記録

既存のEconomyLoopVerifierEditor、EconomyUIVerifierEditor、ResourceTransferVerifierEditor、CraftingVerifierEditor、FirstPersonVerifierEditorを再利用し、換金先変更に伴う期待値を新仕様へ更新する。現在の特異点を換金先とする検証を、旧動作の保証として残さない。

納品規則には、複数資源、予約中の段階遷移、取消、全量超過、同時入力、上限、購読からの再入、再開始による初期化の対象検証を追加する。UIは1600×900・1366×768、長い品目名・多数の要求品、左タブの開閉、一人称への往復を確認する。自動再生は消音する。ビルドはユーザーの明示依頼がある場合だけ行う。

作業状態・対象差分・実行条件・結果はローカルの既存運用に従って記録する。タスクリストへの登録や更新にはTaxisを使い、この計画内の順序を正式タスクIDとして扱わない。実装完了時に現行仕様とコード参照を更新し、計画だけを実装済みとして扱わない。

出荷セルの現行仕様・初回経路・検証入口は[初期特異点と出荷セル](../spec/currency-singularity.md)を参照する。累計納品・目標編集・通知とHUDの責務も同仕様に記録した。初期目標数は木材40・石40 → 板材30・石レンガ20 → 建築部材20の仮値である。今回はユーザー指定の1〜4（累計、設定、判定、表示）を実装し、上表5の通し確認は実施していない。
