# セル種類別の強化

タグ: `現行仕様` `PRG-03` `設備強化` `支出取引` `状態維持`

## 採用した操作

2026-11-09のユーザー採用1Aにより、一基ずつの個別強化購入UIを[種類別の共有スキル](skill-tree.md)へ統合した。セルを選んだ右側は種類名と在庫・状態の読み取り専用とし、強化はスキルノードから適用する。

木材採取・石材採取は抽出量と在庫容量、基本加工・上位加工は種類ごとに入力容量と出力容量を別系統にする。保管庫の容量、搬出路の搬送量と合わせて10系統・各I/IIを持つ。基礎研究50、各I50・II100で、各ノードの倍率・加算値を対象能力へ設定する。同種の既設・非アクティブ・新設セルが同じ設定を読む。

## 所有と取引

`GridFieldDatabaseAdapter.StatEffects`が一プレイの種類・能力別設定を所有し、`SaveCell`が既存・新設セルへ同じ参照を渡す。各セルの`ProgressionType`で型を識別し、対象能力の倍率・加算値を読む。スキルの取得・支払い・通知は`SkillTreeApplication`へ集約する。種類別のスキル購入を唯一の強化入口とする。

基礎値に倍率を掛け、加算値を足して小数部を切り捨て、有効値を1以上とする。容量は取得直後から増加し、実行中の抽出量・搬送量・加工計画は開始時の値を使う。次の周期・取得から新しい数量を使う。座標・方向・接続・Identity・在庫・予約・保持IDと稼働状態を保つ。

旧割合強化、個別購入、セル単位のレベル設定と専用検証は撤去した。再開始時は種類・能力別設定を倍率1・加算0、未取得状態へ戻る。

## 検証

[SkillTreeVerifierEditor.Run](../../Assets/Scripts/Progression/Editor/SkillTreeVerifierEditor.cs)が種類別の取引と効果範囲、既設・新設・再有効化、実行中の抽出・搬出・加工、予約と在庫の保持を検証する。UIと実際の換金収益による再投資は[スキル仕様](skill-tree.md#検証入口)の既存入口を使う。実行記録はローカルの`docs/verification/type-skills.json`へ集約する。
