# セル種類別の共有スキル

タグ: `現行仕様` `PRG-03` `成長` `通貨` `種類別強化`

## 取得条件と効果

2026-11-09、ユーザーが1Aを採用した。従来の採取・搬送・保管の共通3系統と一基ずつの購入UIを、セル種類別のスキルへ統合する。一プレイで一つの取得状態を持ち、MainSceneの共有残高から購入する。取得状態と能力別設定は再開始で初期化する。定義は[SkillTree.asset](../../Assets/Scripts/ScriptableObject/SkillTree.asset)に集約し、起動時に不変カタログへコピーする。

基礎研究は50で、8系統のIを解放する。各Iは50、各IIは100で、IIの前提は同系統のI。価格・倍率・加算値はノードごとに編集できる。

| uidの接頭辞 | 対象 | 強化する能力 |
| --- | --- | --- |
| wood-extraction | 木材採取 | 抽出量 |
| wood-capacity | 木材採取 | 在庫容量 |
| stone-extraction | 石材採取 | 抽出量 |
| stone-capacity | 石材採取 | 在庫容量 |
| storage-capacity | 保管庫 | 容量 |
| crafter-input | 加工設備 | 入力方向ごとの容量 |
| crafter-output | 加工設備 | 出力容量 |
| export-transfer | 搬出路 | 搬出時に取得する数量 |

各系統にI/IIを持ち、木材採取・抽出量はUI表示確認のためVIIIまで伸ばす。全22強化ノードと`basic-research`の計23ノードを使う。木材抽出量III〜VIIIは直前の段階を前提に、価格150・200・250・300・350・400、倍率4・5・6・7・8・9、加算0とする。初期設定はIが倍率2・加算0、IIが倍率3・加算0。取得したノードの値を対象種類・能力へ設定する。前段階への乗算ではなく、常に基礎値から計算する。抽出量と在庫容量、入力容量と出力容量を独立して変更し、既設・非アクティブ・新設セルへ同じ設定を適用する。

通常搬送路は、現状の搬送量プロパティを実際の受領・中継に使わないため、今回の強化対象から外す。速度強化などの追加仕様は、後処理を優先するユーザー指示に従って保留する。通常搬送の数量・速度は現状を保つ。

空・資源・特異点は強化対象外。交差搬送路は上流から渡された固定数量をそのまま中継し、独立した搬送量を持たないため、効果のない強化ノードを追加しない。稼働中の抽出量・搬送数量・加工計画と、在庫・予約・位置・方向・接続・Identityは[有効能力仕様](effective-stats.md)に従って保持する。

## 表示と操作

左の樹形図でノードを選ぶと、右に対象種類、対象能力の倍率・加算値、価格付きの「適用する」を表示する。選択だけでは支払わない。未解放は暗いグレー、解放済みの残高不足は通常色、選択は白枠、適用済みは記号で示す。ノードは40×40の四角とし、名前はノード内へ置かず右側詳細へ集約する。種類別の枝は64以上の間隔で配置し、8系統を横方向へ配置する。狭い画面で枝が収まらない場合は横ドラッグとスクロールバーで移動できる。選択ノードを表示範囲へ寄せ、選択内容が同じ更新ではスクロール位置を保つ。

セルを選んだ右側の状態欄は、種類名・在庫・加工や停止状態の読み取り専用とする。個別の強化購入ボタンは表示しない。スキル間の選択は右枠を閉じ直さず、色を途中の通常色へ戻さず更新する。

残高不足と配置の重なりはUIへ表示する。生成・初期化・対象消失などシステム上の失敗はConsoleへ記録する。

## ScriptableObjectの編集

SkillTree.assetのNodesを編集する。1要素が1ノードで、設定項目は次の8つ。

| 項目 | 用途 |
| --- | --- |
| Uid | 重複しない識別子 |
| Label | 右側詳細に表示する名前 |
| Price | 1以上の価格 |
| Prerequisite | 前提ノードのUid。前提なしは空欄 |
| Cell Type | 対象種類。基礎研究はNone |
| Stat | 対象能力。種類に対応する能力を選ぶ |
| Multiplier | 基礎値へ掛ける倍率。0以上 |
| Addition | 乗算後に加える整数。0以上 |

計算は`max(1, floor(基礎値 × Multiplier ＋ Addition))`。基礎値50に倍率1.5・加算7なら82、次のノードが倍率2.25・加算3なら115となる。倍率0・加算80なら固定値80になる。倍率と加算値の両方が0、負値、非有限値、int上限超過は拒否する。既存セルの能力が下がる設定も購入できない。

起動時に不変カタログへコピーするため、編集後は再生し直して確認する。Has Effect、Branch、Bonus Percent、Has Cell Type Effect、Target Levelと旧購入経路は撤去した。基礎研究はCell Type=None、倍率1・加算0とする。

## 定義と購入の検証

Domainは空定義、nullノード、空uid・名称、価格0以下、uid重複、前提欠落、自己参照・循環を拒否する。種類別効果は対象5種類と対応能力を検証する。同じ種類・能力を変更する複数ノードは前提関係でつなぎ、別枝からの上書きを拒否する。価格は正のlongで、既存の支出予約によって不足を判定する。

`SkillTreeApplication`は取得状態、購入可否、支出予約と確定を管理する。予約後に取得状態・前提・共有状態を再確認し、不成立なら予約を取り消す。取得状態と能力別設定を通知せず更新してから支出を確定し、その後に共有能力とツリーを通知する。残高の確定通知から更新済み能力を読める。通知中の再入と同じuidの二重支払を拒否し、通知先の例外は記録して残りの購読者へ通知する。

能力別設定はグリッド所有の`SharedStatEffectsApplication`が保持する。セルの`ProgressionType`が種類と能力に対応する共有状態を読むため、一基ずつの更新・再生成・再初期化を行わない。割合強化の定義・購入処理と、個別レベルの設定・購入入口は撤去し、検証も種類別強化へ揃える。

## 検証入口
