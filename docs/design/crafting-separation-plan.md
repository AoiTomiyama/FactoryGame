# 加工処理の責務分離計画（タスク F）

タグ: `実装計画` `タスクF` `加工` `レシピ` `Domain` `Application`

状態: 2026-10-06 に現行コードから立案。実装は次タスクの許可後に開始する。

## 目的と現在の実装

加工セルのレシピ成立判定と素材消費を Unity 非依存の処理へ分離する。判定時に選んだ入力と、確定時に消費する入力を同じ計画で扱い、不成立・容量不足・中断時は数量を変更しない。

現在の [CrafterCellAdapter](../../Assets/Scripts/Cells/Adapter/CrafterCellAdapter.cs) は `HasAvailableRecipe` / `CheckRecipe` で入力を検索し、加工時間の経過後に `Craft` で再び検索して消費する。レシピ検索、素材と入力の対応付け、数量更新、待機、Tween、UI 更新が同じクラスにある。判定と消費にはほぼ同じ検索が重複している。同種素材が複数入力にある場合、列挙順による先取りで成立可能な対応を見落とす余地がある。

## 守る仕様

- レシピは定義配列の順に選ぶ。
- 現行の「一つの材料条件を一つの入力が全量満たす」「同じ加工の材料条件へ同じ入力を重複割当しない」契約を維持する。複数入力の数量合算は別の仕様判断とする。
- 搬入予約量は素材の現在量と区別する。加工で既存の予約を消費・取消しない。
- 加工時間の終了と確定条件の再確認を経て、素材消費と成果物追加を一度だけ反映する。
- 中断・セル削除・成立条件喪失では素材と成果物を変更しない。完了済み加工の再確定を拒否する。

## 配置と責務の案

| 配置 | 型の候補 | 責務 |
| --- | --- | --- |
| `Crafting/Domain/` | `RecipeRulesDomain` | 入力と材料条件の対応付け、数量・出力容量の判定、確定後の数量計算 |
| `Crafting/Domain/` | `RecipePlanDomain` | 入力識別子、素材消費量、成果物種別・数量を持つ変更不可の計画 |
| `Crafting/Application/` | `CraftingOperationApplication` | 選択した計画と加工の進行状態、確定・取消の一回性を管理する。Unity のセル・Tween・UI は参照しない |
| `Crafting/Adapter/` | `CrafterCellAdapter` | シーンの入出力、定義からの変換、非同期処理の寿命、時間・演出、検証済み数量の反映と UI 通知 |
| `Crafting/Definitions/` | 既存のレシピ定義 | 編集可能なレシピを入力として提供する |

加工セルを移動する場合も `.meta` の GUID とシリアライズするフィールド名を保つ。入力識別は Unity の座標ではなく単純な識別子を使い、座標への対応は Adapter に残す。型の追加は実際に分離する責務に限定する。

## 実装手順

1. 既存レシピと加工セルから入力・出力・予約の契約を確認し、現行仕様と追加判断を区別して記録する。
2. Domain に数量スナップショットを渡し、成立する材料と入力の組み合わせを求める。数量の異なる同種入力でも列挙順だけで失敗しない対応付けにする。
3. 成立した対応を消費計画に保存する。加工完了時は同じ対応を現在の数量と照合し、全条件が成立した場合だけ更新後の数量を返す。一部消費してから失敗する経路を作らない。
4. Application で計画の寿命と確定・取消を管理する。Adapter は数量反映前に中断とセルの寿命を確認し、すべての数量を反映した後に UI を更新する。
5. 加工セルの重複した検索・消費処理を置き換え、現行仕様、設計方針、タスク F の検証証拠を更新する。

## 完了条件と検証

- Unity 非依存でレシピ成立・素材消費を検証でき、Domain / Application が `CrafterCellAdapter` を参照しない。
- 同種素材の複数入力、数量の異なる入力、材料不足、出力容量の上限、ゼロ・負数、数量上限付近を確認する。
- 材料条件の重複割当、不成立時の部分消費、計画の二重確定を防ぐ。
- 加工開始後の搬入・状態変化でも、計画と予約量を維持しながら確定条件を再確認する。
- Play Mode で正常完了、加工途中の取消・削除、搬入予約との連携を確認する。既存の予約・搬送検証も必要な範囲で通す。
- Editor コンパイルとプレイヤービルドの結果を記録する。
